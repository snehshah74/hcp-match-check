HCP match check

Match every CRM physician to the right provider. You only see the unclear ones.

How it decides
  1. Read the row: drop "Dr." and credentials, handle "Last, First", map nicknames (Mike → Michael), site aliases (St Mary Med Ctr → Saint Mary Medical Center) and specialty wording through fixed tables.
  2. Check the NPI: 10 digits and a Luhn check digit computed with the 80840 prefix. A failed check is flagged as a typo and never used.
  3. Search the registry in the same state: same last name, one typo away, or first and last swapped, plus whoever owns a typed NPI.
  4. Weigh name, NPI, current site, past site, city and specialty as separate evidence. Another person's NPI, a different specialty or middle initial counts against.
  5. Link only if the name and a second fact agree, nothing counts against, and no namesake passes too. Otherwise it's yours.
  6. Then flag deactivated NPIs, accounts that aren't a recent site (a likely move) and two rows for one person. Changes are drafted, never written.

All rules, no AI model. In production a model could propose matches for messy rows, but only these same evidence rules could accept one.

Limitations
  • Synthetic data: registry, sites and CRM exports come from a seeded generator. Synthetic NPIs start with 2, a range not yet issued, so none is a real person's.
  • Nicknames, site aliases and specialties outside the fixed tables aren't understood; those rows come to you.
  • The evidence rules are mine. They trade more rows for you against zero wrong links.
  • A move can't be flagged until the row is linked, so ambiguous rows that moved are caught only after you pick.
